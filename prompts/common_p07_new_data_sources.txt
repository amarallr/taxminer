## C — CONTEXT
TaxMiner is an independent, non-official research project on public Receita Federal Solucoes
de Consulta (`tax_consultation_decisions`) and company financial notes
(`financial_disclosures`), with three independent MVP gates. Current state (verify in
`docs/project_management/project_status.md`, `work_items.csv` and `handoff.md`): Phase 1.1 is
suspended (`decision_0020`); Phase 1.2 is in progress (`work_0011`) and a long-running DFP
collection is executing from `src/collect/` into `TAXMINER_DATA_DIR` (`decision_0022`,
`risk_0013`). TaxMiner's R code uses base R plus `renv`/`testthat` only, en-US snake_case
names, `docs/project_management/` registers and explicit human acceptance per work item.

TaxMiner is adding new public data sources. The reference implementation (the "source") is a
tested R 4.5.1 pipeline over CVM open data for investment funds: FIDC monthly reports
(configuration P04, download P05_01, temporal consolidation per layout P06_01, evidence-based
acceptance P07) and FII monthly reports (P05_02, P06_02), plus shared contracts (P02:
contained destination paths, validated atomic writes with rollback, recoverable RDS,
SHA-256 and code/transformation signatures, attempt registry, execution policy that
separates checkpoint reuse from download refresh) and environment checks (P03). Its names,
messages and docs are in pt-BR; its prompts are CO-STAR with requirement IDs `PNN[_SS]-RF/RNF/TST-NNN`.
Prefer the source's prompt pack 1.1 (revised traceability) when present; otherwise use the
`IDs to reconcile` method described in stage 00.

Important differences: FIDC/FII fund reports are NOT within any current TaxMiner MVP scope;
the reference repository has no LICENSE file while TaxMiner is MIT; the source depends on
`data.table`, `httr2`, `digest`, `jsonlite`, `dotenv` (and optional `arrow`); its CI runs on
Windows and Linux, TaxMiner's on Windows; its tests use `p02_testar.R`, TaxMiner's use
`scripts/validate_environment.R` and `tests/testthat/test_*.R`; in the source, `tmp/` holds
local instructions, while in TaxMiner `tmp/` is a protected area.

## O — OBJECTIVE
Add new data sources to TaxMiner, reusing what the reference implementation proves, in a governed, traceable and
reversible way, without changing the source repository, without disturbing the running DFP
collection, and without expanding TaxMiner's scope unless the developer explicitly decides so.
Two independent value streams must be evaluated and decided separately:
1. **Shared reliability primitives** (from P02/P05_01/P07) that may strengthen
   `src/common/` and the Phase 1.2 `financial_disclosures` pipeline.
2. **A new, independent source family** for CVM fund monthly reports (proposed technical
   name `investment_fund_reports`, with `fidc_monthly_reports` and `fii_monthly_reports`),
   which would be an optional module outside the three MVP gates, with its own requirements,
   tests and human acceptance gate.

## MANDATORY MVP ROADMAP (PROMPT PACK 1.0; RESTRUCTURED BY decision_0025)
- **MVP Phase 1 — Data Collection, Structuring and Search:** three independent subphases, one per source family. Each has its own schema, provenance, coverage, quality, tests, local Shiny search area and explicit human acceptance; none depends on another.
  - **Phase 1.1 — Tax Consultation Decisions:** independently discover, acquire, process, consolidate in Parquet, and search public RFB Solucoes de Consulta; provide a working local Shiny search, original document references, tests, and explicit human acceptance.
  - **Phase 1.2 — Financial Statement Notes:** independently discover, acquire, process, consolidate in Parquet, and search public explanatory notes from companies' financial statements; provide company/CNPJ/period/note filters, source references, tests, and explicit human acceptance.
  - **Phase 1.3 — Investment Fund Reports:** independently discover, acquire, consolidate in Parquet, and search public CVM fund reports for FII, FIDC, FIP and FIAGRO (`investment_fund_reports`); provide family/fund CNPJ/administrator/period filters, source-file citations, tests, and explicit human acceptance.
- **MVP Phase 2 — Cross-Source Intelligence:** evidence-based relationships between the bases accepted in Phase 1, always as cited hypotheses with side-by-side source citations, confidence/uncertainty, traceability, tests and human review. It consumes only subphase datasets that have explicit human acceptance. No automatic findings of misconduct.
Track implementation, testing, human acceptance, release and operational health separately FOR EACH subphase and phase. Subphases 1.1–1.3 run independently; Phase 2 work may start before every subphase is accepted only when its documented dependencies are satisfied; no phase can be marked accepted without human sign-off. Keep one local Shiny interface with independently enabled functional areas.
Naming: `tax_consultation_decisions` is the technical document family for Solucoes de Consulta; `financial_disclosures`/`financial_notes` for corporate reports and notes; `investment_fund_reports` (subfamilies `fii`, `fidc`, `fip`, `fiagro`) for CVM fund reports; `document_relationships` for cross-source evidence. Preserve the original Portuguese legal title and document type. Do not equate Solucoes de Divergencia, Pareceres Normativos or other administrative acts with Solucoes de Consulta: use separate typed classifications under a broader `tax_interpretive_decisions` umbrella if scope expands. Do not use `tax_rulings`, `ruling_id`, or 'Tax Rulings' in newly authored artifacts.
Protected `restricted/` and `tmp/` stay inaccessible to Codex and other remote agents; local-only independent Git history may be managed by the developer, but must never be synchronized or published.
Anything shared from the reference implementation is a `common` capability; it never produces findings of misconduct.
